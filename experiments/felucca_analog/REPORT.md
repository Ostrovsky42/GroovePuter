## B3. Нативные 22,05 кГц

**Форк** (`fork22k/`; отличия от `vendor/felucca/` — только в `FORK.diff`):
- `dsp.c`: нижняя граница FS 32000 → 16000. Остальное без изменений.
- `tools/gen_engine_tables.py`: `FS_MIN` 32000 → 16000; `pitch()` больше не режет инкремент по `0x7FFFFFFF`. Таблица `uint32_t`, при 22,05 кГц максимум инкремента `0,60·2^32`, т.е. всё умещается. Прежний кап был лишним: именно он давал 51 зажатый шаг.
- `eng_analog.c` и `felucca_engine.h`: без изменений.
- Таблицы на 44,1 кГц, сгенерированные форком, побайтно совпадают с таблицами vendor (`cmp`).

**Граница высоты.** Музыкальная граница — 0,45·FS (upstream ограничивает срез тем же значением). При 22,05 кГц это MIDI 122 (9,4 кГц). Адаптер держит ноты выше границы на MIDI 122 и **считает** их (`fa_range_clamps`). Тест 124–127: по одному срабатыванию на каждую ноту. Это явное поведение, а не тихое превращение в другую высоту.

**Тон, MIDI 24–96** (фильтр по умолчанию, окно 0,6 с, FFT 8192):
- 22,05 кГц: максимум |ошибки| 6,3 цента.
- 44,1 кГц: максимум 11,6 цента.
- Разница — разрешение окна на низких нотах (MIDI 24–30), не движок.

**Верхний регистр, MIDI 100–122, фильтр открыт:** ошибка ≤ 0,12 цента на обеих частотах, включая MIDI 122.

Заметка: на MIDI 122 с фильтром по умолчанию основной тон почти не слышен. KTR поднимает срез с высотой, но фильтр всё равно сильно режет 9,4 кГц. Это свойство фильтра, не ошибка тона.

**Неграмоническая доля** (прокси алиасинга, фильтр открыт; медиана / p90 по нотам):

| Диапазон | Нативно 22,05 | Эталон 44,1 | Децимация 2:1 |
|---|---|---|---|
| MIDI 24–96 | 0,019 / 0,098 % | 0,005 / 0,012 % | 0,026 / 0,148 % |
| MIDI 100–122 | **0,51 / 1,78 %** | 0,059 / 0,103 % | 0,009 / 0,62 % |

На верхнем регистре нативная версия даёт около 9× больше неграмонической энергии, чем эталон: это алиасинг. Децимация по медиане не отличается от эталона, но её p90 заметно шумнее эталона; причина не выяснена. Метрика на уровне 0,01–0,1 % близка к шуму окна (боковые лепестки Ханна), поэтому отдельные ноты она не ранжирует. Спектры пиков h1–h4 у нативной, децимированной и эталонной версий различаются на доли дБ (проверено на MIDI 101).

**Ограничения 22,05 кГц, которые остаются:**
- срез фильтра прижат к 0,45·FS ≈ 9,9 кГц (яркость ниже, чем при 44,1 кГц);
- частота задаётся при сборке: `setSampleRate()` интерфейса `IMonoSynthVoice` не реализуем на рантайме без отдельного набора таблиц на каждую частоту;
- ноты выше MIDI 122 не играются (зажимаются и считаются).

## B4. Децимация 44,1 → 22,05 кГц

- FIR: 145 отводов, Kaiser-окно β = 5,65, срез 10,47 кГц при 44,1 кГц.
- Пульсация полосы 20 Гц … 9,9 кГц: ≤ 0,009 дБ. Подавление от 11,025 кГц: −58 дБ.
- Стоимость: 145 MAC на выходной сэмпл, т.е. ~3,2 MMAC/с при 22,05 кГц. Плюс рендер движка на 44,1 кГц, т.е. вдвое больше сэмплов в секунду.
- На хосте рендер движка: 8,1 нс/сэмпл при 44,1 кГц и 8,9 нс при 22,05 кГц. Значит, на секунду звука рендер 44,1 кГц стоит ~357 мкс, рендер 22,05 кГц ~196 мкс (без FIR). FIR на хосте в C не измерен — цифра выше из счёта MAC. **На ESP32-S3 эти числа не переносятся; решение о пути должно опираться на замер на устройстве.**
- Мелодия: RMS нативной 0,2498 против децимированной 0,2491 (разница 0,03 дБ).

## Уровень (калибровка `engineOutputGain`)

Сырой выход (`gain=65536`), RMS по 1-секундным удерживаемым нотам MIDI 36, 48, 60, 72, 84; относительно SH101 на тех же нотах:

| Пресет | Среднее, дБ к SH101 (сырой) | После 0,44 |
|---|---|---|
| INIT (одиночная пила) | +9,7 | +2,7 |
| DUAL SAW | +6,1 | −0,9 |
| DEEP BASS | +4,7 | −2,3 |
| ACID LEAD | +7,4 | +0,4 |

Среднее по пресетам: +7,0 дБ при 22,05 кГц и +7,1 дБ при 44,1 кГц → коэффициент 0,44. Стартовое 0,40 отличается от среднего на ~0,6 дБ; среднее выбрано как более честный центр. Пресеты **не выравниваются автоматически**: разная динамика — часть звука (у баса и кислоты короче сустейн, поэтому ниже RMS). Разброс между пресетами ~5 дБ — решение для слуха, не для метрики.

Пик INIT в мелодии 1,02 (float, до мастера GroovePuter) — чуть выше полной шкалы. Проверяется в цепочке мастера, не здесь.

## Звук по умолчанию: INIT = одиночная пила

Одиночная пила (MIX 0, только OSC 1) соответствует закону 1/n в пределах 1–2 дБ на 44,1 кГц (проверено в раунде 1, не менялось). Пресеты:
- **INIT** — пила, срез 600 Гц, RES 0,6, ADSR 3 мс / 250 мс / 0,3 / 50 мс.
- **DUAL SAW** — квадратурная пара (MIX 64), тот же срез.
- **DEEP BASS** — WAVE SUB (пила + квадрат на октаву ниже), срез 40, RES 50, ADSR 3 мс / 400 мс / 0,6 / 60 мс.
- **ACID LEAD** — пила, срез 50, RES 110, DRV 20, KTR 90, ADSR 3 мс / 150 мс / 0,2 / 40 мс.

ADSR — допущение адаптера. Пресеты задают стартовые точки, не финальный звук.

## Замер на Cardputer (ESP32-S3, 240 МГц)

Отдельный скетч `hw_bench/` (не GroovePuter, не в её прошивке). Каждый движок рендерит 1 с удерживаемой ноты блоками CTL = 32; `esp_timer` даёт время по блокам. Первый прогон отбрасывается. Сырые строки — `hw_bench/results/`.

Загрузка CPU одного голоса (движок без аудиоцепочки):

| Движок / путь | Частота | Загрузка | Самый длинный блок / бюджет блока |
|---|---|---|---|
| Felucca INIT | 22,05 кГц (нативно) | **2,27 %** | 40–45 мкс / 1 451 мкс (3 %) |
| Felucca DUAL SAW | 22,05 | 2,24 % | 38–46 мкс |
| Felucca DEEP BASS | 22,05 | 2,75 % | 45–69 мкс (4,8 %) |
| Felucca ACID LEAD | 22,05 | 2,60 % | 45–63 мкс (4,3 %) |
| SH101 | 22,05 | 8,01 % | 122–151 мкс (10,4 %) |
| WAVEMORPH | 22,05 | 4,21 % | 67–92 мкс (6,3 %) |
| Felucca INIT (рендер) | 44,1 кГц | 4,55 % | 42–48 мкс / 726 мкс |
| SH101 | 44,1 кГц | 15,99 % | 122–148 мкс (20,4 %) |
| WAVEMORPH | 44,1 кГц | 8,42 % | 68–82 мкс |
| FIR 145 отводов, 2:1 → 22,05 кГц | из 44,1 | **6,96 %** | 105 мкс / 1 451 мкс (7,2 %) |

Децимационный путь (44,1 рендер + FIR) = 4,55 + 6,96 = **11,5 %** на голос. Нативный путь = 2,27 %. Нативный путь дешевле примерно в 5 раз.

Память на устройстве: Felucca voice 84 Б, таблицы 3 588 Б; свободная куча в начале 342 492 Б, в конце 341 812 Б (−680 Б за прогон, вероятно буферы Serial), самый большой свободный блок 270 324 Б. Объекты SH101 и WAVEMORPH на устройстве 296 и 292 Б.

**Что это означает.** Цифры — один голос в изоляции. Полифония не измерена; если умножать, то 2,3 % на голос при полифонии становится прогнозом, а не результатом. Заявлять «8 голосов = 18 %» по этим данным нельзя. Для этого нужен бенч полифонии и аудиоцепочка. Тот же «прогноз» по SH101 тоже нельзя переносить на GroovePuter без замера внутри прошивки.

Сравнение пути: нативные 22,05 кГц дешевле в 5 раз, но алиасинг на верхнем регистре (медиана 0,51 % против 0,059 % у эталона, см. выше). Децимация по медиане чистая, но стоит 11,5 % CPU на голос. Выбор — между CPU и алиасингом на верхних нотах, и он должен решаться на слух (блиндтест), а не по одной метрике.

## Что не измерено (не сделано, не заявлено)

- **CPU в прошивке GroovePuter.** Замерен изолированный голос (см. раздел выше), не полифония и не аудиоцепочка прошивки. Underruns не измерены.
- **Heap и underruns внутри GroovePuter.** Бенч измеряет кучу изолированного скетча; в прошивке она другая.
- **Полная DRAM прошивки.** Интеграции нет; измерен только объектный файл адаптера.
- **Слепое A/B-прослушивание.** Требует людей. WAV подготовлены (см. ниже).
- **Аппаратная работоспособность звука.** Замерен CPU, но не слышно, что звук правильный на плате. Для этого нужен блиндтест.
- **Прошивка GroovePuter на плате.** После бенча на плате стоит `hw_bench`, а не GroovePuter. Восстановление нужно сделать отдельно.

## Решение

**RESEARCH MORE**, с более узким вопросом, чем в раунде 1. CPU на железе замерен (см. выше), и нативный путь стоит в 5 раз меньше децимации.

- Нативные 22,05 кГц: тон точен на всём диапазоне MIDI 24–122 (≤ 0,12 цента на верхнем регистре; ≤ 6,3 цента на низком при разрешении окна). Алиасинг на верхних нотах ~9× эталона по медиане — главный минус нативного пути.
- Децимация 2:1 с FIR устраняет алиасинг по медиане и не меняет спектр пиков, но стоит 11,5 % CPU на голос против 2,3 % нативно (замер на Cardputer).
- Пресеты, одиночная пила по умолчанию и коэффициент 0,44 — решения для слуха и интеграции; их можно принимать без замера.

Следующий шаг, который меняет решение: **слепое A/B-прослушивание** нативного и децимированного путей (алиасинг на верхних нотах против качества) и **бенч полифонии внутри аудиоцепочки** GroovePuter. Без них переход к production-интеграции не обоснован.

## Воспроизведение

```sh
sh experiments/felucca_analog/run_all.sh   # ~15 минут: сборки, WAV, анализ, FIR, санитайзеры, out/checksums.sha256
```

Требования: `cc`, `c++` (C++17), `python3`. Для размеров ESP32 — `xtensa-esp-elf` (Espressif). Ничего не скачивается: upstream лежит в `vendor/`, форк — в `fork22k/`.

В этом раунде `run_all.sh` выполнен один раз (828 WAV с контрольными суммами). Повторный прогон для проверки детерминизма после изменений не делался; в раунде 1 два прогона дали одинаковые хеши на том же коде движка.
