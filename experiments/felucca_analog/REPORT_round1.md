# DSP-B — Felucca ANALOG: инженерный отчёт

**Решение: RESEARCH MORE.** Не ADOPT: нет слухового вердикта, 22,05 кГц вне поддерживаемого диапазона upstream, нет ESP32-замера, а огибающая/accent/slide у движка не определены. Не REJECT: точность тона, устойчивость, память и CPU на хосте выглядят хорошо, а алиасинг на 22,05 кГц в тесте меньше, чем у SH101.

## База и источники

- GroovePuter: база `af4d5107` (`docs: record accepted integrated Cardputer firmware`), ветка `experiment/dsp-b-felucca-analog` (worktree от этого SHA; рабочее дерево основного checkout не трогалось).
- Felucca-Engines: `hugelton/Felucca-Engines` @ `04ffe903eb87a752305d1e5b10da01b53e4ab004` (2026-10-16), лицензия MIT, (c) 2026 Leo Kuroshita, Hügelton Instruments. Файлы `felucca_engine.h`, `dsp.c`, `eng_analog.c`, `tools/gen_engine_tables.py` скопированы без изменений в `vendor/` вместе с `LICENSE`.
- Upstream собирается и проходит свои тесты на хосте (`sh tests/run.sh`: 122 рендера, ASan/UBSan чистые).

## B1. Аудит

| Параметр | Значение |
|---|---|
| Поддерживаемые частоты | 32000 … 96000 Гц (`dsp.c`: `#error` ниже 32000; `gen_engine_tables.py`: `FS_MIN`) |
| Причина нижней границы | верхняя нота 13,2 кГц выходит за Найквист ниже ~26,5 кГц |
| Блок управления | CTL = 32 сэмпла (1,45 мс при 22,05 кГц) |
| Состояние голоса `voice_t` | 84 Б на голос |
| Таблицы (`fe_tables.h`, 44,1 кГц) | 3588 Б: SINE 2050 + PITCH_OCT 768 + SVF_G 256 + TANH_Q15 514 (const → flash) |
| Арифметика | целочисленная (int32, Q15/Q12/Q16), float в движке нет |
| Стоимость | см. B3 (только хост) |

**Ограничения на 22,05 кГц** (проверено сборкой, а не чтением):
- Генератор таблиц падает на собственной проверке `pitch()`: при FS = 22050 ноты выше ~MIDI 124,8 упираются в clamp `0x7FFFFFFF` — **51 из 2048 шагов** (3 верхних полутона). Мелодия их не играет, но это дыра.
- `dsp.c` отказывается собираться ниже 32 кГц. Для эксперимента сборочная копия понижает эту границу до 16 кГц (`build.sh`, `sed`); остальной файл идентичен vendored-версии.
- Срезы выше 0,45·FS (≈ 9,9 кГц) прижимаются к этому пределу (документировано в upstream). Яркость ANALOG на 22,05 кГц ограничена.
- Частота задаётся на этапе компиляции: `FS`, `FE_*` константы и таблицы генерируются в build-time. Поэтому `IMonoSynthVoice::setSampleRate()` **не реализуем** на рантайме без отдельного набора таблиц на каждую частоту.

## Сопоставление с `IMonoSynthVoice`

| Метод | Felucca ANALOG | Вывод |
|---|---|---|
| `startNote(freq, accent, slide, vel)` | `fa_note_on`; accent = только амплитуда ×1,15 (фильтрового accent в ANALOG нет); slide = glide в адаптере | реализуемо, accent и slide — придумывать на стороне порта |
| `release()` | `fa_note_off` → ADSR-release в адаптере | реализуемо |
| `process()` (по сэмплу) | буферизация по блокам 32 | реализуемо |
| `parameterCount` / `getParameter` | `param_desc_t` (label, min, max, F_ENUM) → `Parameter` (в т.ч. options для WAVE) | реализуемо; 8 EDIT + ATK/REL |
| `setSampleRate(float)` | константа времени сборки | **не реализуемо** на рантайме |
| `setMode` / `setLoFiAmount` | нет аналога в ANALOG | заглушка или отображение |
| Огибающая | движок её не содержит — это задача хоста (`voice.c`) | нужна отдельная спецификация |

## B2. Прототип

`experiments/felucca_analog/`:
- `fa_analog.c` — адаптер на C: один голос, ADSR (фиксированные 3 мс / 250 мс / 0,3 / 50 мс), Q15-рамп амплитуды по блоку, glide для slide, точная частота через остаток 1/4096. Движок вызывается без изменений (`analog_note_on`, `analog_render`).
- `fa_driver.cpp` — один патч для трёх движков, мелодия, sustain, стресс, CPU. SH101 и WAVEMORPH собираются из `src/dsp/` без изменений.
- `analyze.py` — метрики на чистом Python (в окружении нет numpy).
- `make_tables.py` — генератор таблиц с обходом проверок (только для эксперимента, в отчёте перечислено).
- `run_all.sh` — воспроизведение всего; результаты в `out/` (git-ignored) с `checksums.sha256`. Два прогона дают идентичные хеши.

Адаптер — допущение эксперимента, а не upstream-поведение: огибающая, glide, accent и уровень задаются здесь. Поэтому метрики огибающей не являются вердиктом по звуку движка.

## B3. Сравнение (хост, одинаковый патч: пила, срез ~600 Гц, RES 0,6, Sub выключен у SH101/WAVEMORPH)

**Тон (sustain, MIDI 45 = 110 Гц, MIDI 84 = 1046,5 Гц, MIDI 99 = 2489 Гц):** ошибка ≤ 1,4 цента у всех трёх при 22,05 и 44,1 кГц (разрешение FFT-бина).

**Пила: чистота и дизайн звука.** Режим `mix0` (только OSC 1, фильтр открыт, 1046 Гц) даёт гармоники h2…h8 = −5,6 … −22,9 дБ при 22,05 кГц и −6,8 … −20,6 дБ при 44,1 кГц; закон 1/n даёт −6 … −18 дБ. То есть **путь пилы корректен**.

Но ANALOG по умолчанию (MIX 64) — это две пилы, второй осциллятор стартует с четверти периода (`ph[1] = ph[0] + 0x40000000`). Чётные гармоники гасятся: h2 −46…−60 дБ, h6 −56…−88 дБ относительно h1. Это **звук движка, а не ошибка**, но это не «чистая пила», и сравнение с SH101 надо читать с этим.

**Алиасинг (тест: 2489 Гц, фильтр открыт, доля неграмонической энергии, прокси):**

| Движок | 22,05 кГц | 44,1 кГц |
|---|---|---|
| FELUCCA_ANALOG | 0,17 % | 0,03 % |
| SH101 | 0,30 % | 0,06 % |
| WAVEMORPH | 6,19 % | 1,33 % |

Прирост алиасинга у Felucca на 22,05 кГц есть, но он меньше, чем у SH101 и WAVEMORPH. Метрика — прокси, а не слуховая оценка.

**Уровень (мелодия, 22,05 кГц):**

| Движок | RMS | пик | коррекция до RMS SH101 |
|---|---|---|---|
| FELUCCA_ANALOG | 0,374 | 1,479 | −8,2 дБ |
| SH101 | 0,146 | 0,521 | 0 |
| WAVEMORPH | 0,108 | 0,353 | +2,6 дБ |

Сырой выход Felucca в адаптере на ~8 дБ громче по RMS и выходит за полную шкалу (1,48) до какого-либо мастера. В upstream комментарий говорит «пик около −6 dBFS до мастера»; мастер в upstream не проверен. Поэтому сравнение слуха — только по согласованной по RMS копии (`matched_*.wav`), и уровень мастера — открытый вопрос.

**Стабильность:** 20 000 случайных нот на движок при каждой частоте, ASan/UBSan (strict), 0 stderr, 0 нефинитных значений → `stress-san-*.txt` (в `run_all.sh` для скорости 5 000).

**CPU (хост x86, `-O2`, минимум из 5 прогонов, не ESP32):**

| Движок | 22,05 кГц | 44,1 кГц |
|---|---|---|
| FELUCCA_ANALOG | 8,9 нс/сэмпл | 8,1 нс/сэмпл |
| SH101 | 13,6 | 13,4 |
| WAVEMORPH | 12,9 | 12,5 |

Эти числа не переносятся на ESP32-S3; разница ~1,6× на хосте — не вердикт.

**RAM:** Felucca — 84 Б на голос + 108 Б состояния части (1 голос в адаптере) + таблицы 3588 Б в flash; SH101 — объект 424 Б; WAVEMORPH — объект 416 Б + wavetables 8×128×int16 = 2048 Б. Для полифонии Felucca умножать 84 Б на число голосов.

## Открытые вопросы

1. **Слух.** Послушай `out/wav-*/matched_*.wav` (мелодия, RMS-выровнено) и `out/sus-*/sustain_*` (ноты). Субъективного вердикта по звуку у меня нет.
2. **22,05 кГц или 44,1 кГц с ресэмплингом.** 22,05 требует форка (пределы выше) и вне контракта upstream; ресэмплинг — неизмеренная цена.
3. **Дизайн звука.** Принимать ли квадратурный дабл-пилу как «звук ANALOG» или ставить MIX по умолчанию в одну пилу.
4. **Уровень мастера.** Как Felucca калибрует мастер относительно GroovePuter.
5. **База DSP-A.** В задаче сказано использовать SHA, который зафиксирует DSP-A с новыми локальными изменениями памяти. Результата DSP-A в этой сессии нет, поэтому взят `af4d5107`. Второй вставленный блок (PR #495, `64ae4b8b`, −4752 Б DRAM) я не применял, пока не подтвердишь, что он входит в базу.
