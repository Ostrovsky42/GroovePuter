# GroovePuter — Critical Review Closure Plan

**Status: PRODUCT POLICY RATIFIED / ACCEPTANCE OPEN**  
Дата проверки репозитория: 2026-10-25.  
Тип изменений: дефекты, существующий UX, тесты, измерения и документация; без расширения функциональности.

## 0. Неизменяемые продуктовые решения

1. **CORE** — генератор развивающегося редактируемого MIDI-материала. Пользователь получает узнаваемый музыкальный мотив, развивает его, редактирует, принимает и сохраняет. Тимбр и устройство вывода не определяют музыкальную семантику.
2. **DSP** — средство надёжного предварительного прослушивания. Его задача — разборчиво воспроизводить материал, а не заменять аппаратные синтезаторы или VST. Число звуковых движков не является KPI.
3. **Feature freeze.** Допустимы только воспроизведённые исправления, минимальные улучшения существующего UX, тесты и измерения. Нет новым генераторам, движкам, платформам, страницам и крупным рефакторингам.
4. **Cardputer ADV** — портативный интерфейс ядра. Сохранять разделение музыкального смысла и аппаратных зависимостей, но не инициировать порт на Android/другую плату.
5. Ближайший релиз — **автономная приёмка**. Обязательны G1/G2/G3/G4/G6/G7; G5 (раздельная запись MIDI в REAPER) явно **DEFERRED**, а не PASS. Не называть автономный релиз завершённым MIDI-first продуктом.

**CORE:** жанрово-ограниченная генерация, 4/8-тактовые TAKE, существующие DEVELOP/BREAK/RETURN и Song/FORM, редактируемые события, KEEP/ACCEPT, Undo, сохранение, логическая независимость MIDI-ролей от звуковых движков.

**SUPPORT:** внутренние Synth A/B и синтезированные барабаны, компактный UI, текущий USB-MIDI transport, мониторинг и диагностика.

**FROZEN:** новые DSP/жанры/алгоритмы, Felucca-интеграция, WAV Sampler/Tape на Cardputer, новые рабочие экраны, новые hardware/мобильные цели, полноценная DAW-автоматизация. Исправление дефекта в поддерживаемом пути не означает разрешение на его расширение.

## 2. Единая политика STOP/GO

**GO TO STANDALONE RELEASE** только если:

- 6/6: G1, G2, G3, G4, G6, G7 = PASS на одном exact release-candidate SHA;
- нет panic, watchdog, audio underrun, неотпущенных нот, потери принятого материала и ложного Save success в обязательных испытаниях;
- независимый reviewer подтвердил файлы доказательств и конкретный BIN SHA-256;
- memory/CPU gate выполнен на устройстве, без замены runtime heap статической DRAM;
- REAPER G5 публично помечен как DEFERRED и не заявлен проверенным.

**STOP RELEASE:** любой FAIL обязательного Gate, необъяснимый reboot, неверный Load, непроверенный образ, регрессия NoteOff/transport или отсутствие первичных доказательств. Порог не снижается задним числом; исправление — узкое, с RED→GREEN и повторной проверкой затронутого сценария.

### Автономные G-gates

| Gate | Заранее заданный PASS |
|---|---|
| G1 — 3 минуты | 3/3 холодных запуска: drums + Synth A + Synth B слышны и синхронны за ≤180 с, без внешней отладки |
| G2 — 16 тактов | A 4B → DEVELOP 4B → BREAK 4B → RETURN 4B через существующие MATERIAL/Song/FORM; два поддерживаемых жанра, 8 заранее фиксированных seed на каждый; ≥6/8 успешных для каждого жанра по голосам ≥2/3 слепых слушателей; различие не сводится к тембру |
| G3 — edit/Undo | Правка Melody, отмена FORM, отмена/отказ DEVELOP; в каждом из трёх кейсов исходный canonical material и Song refs сохраняются, нет чужого Undo/зависших нот |
| G4 — звук | TB303/WAVEMORPH + барабаны через jack и динамик; ≥2/3 слушателей признают бас, лид и общий микс пригодными для наброска; нет повторяемых непреднамеренных clicks/clipping, нет новых underruns |
| G6 — persistence | 3 холодных Save→Reset→Load с A+B 8B, Song refs и HGS; canonical event hash совпадает; unaccepted edit не публикуется; отрицательные SD-случаи не выдают ложный success и не разрушают текущий материал |
| G7 — независимый UX | 3/3 незнакомых с проектом пользователя, Quickstart/Alt+H разрешены, помощь разработчика запрещена; слышимый грув ≤5 минут, полный Generate→Keep→Edit→Undo→Save→Load ≤15 минут |

**G5:** отдельные MIDI-треки REAPER не входят в этот релиз; историческая проверка SEQTRAK/USB не заменяет G5. Не расширять MIDI API ради нынешнего acceptance. Сохранить существующие role/channel contract tests.

## 3. Закрытие девяти критических рисков

### R1. Не выбран главный продукт — 10/10 → цель ≤4/10

**Exit criteria:** одна фраза CORE закреплена в PRODUCT_POSITIONING; у каждого PR есть явное соответствие хотя бы одному G1/G2/G3/G4/G6/G7 или конкретному дефекту; 0 новых неподтверждённых фич за три последовательных PR. Составлены CORE/SUPPORT/FROZEN и список явных non-goals.

**Evidence:** утверждённая продуктовая политика, checklist трёх последовательных PR, дифф README/Quickstart без конфликтующих обещаний.

**GO:** каждое изменение улучшает измеряемый пользовательский путь. **STOP:** запрошен ещё один движок, режим, платформа, жанр либо экран, не связанный с исправлением текущего сценария; переводить в backlog без реализации.

### R2. Математическая корректность подменяет музыкальность — 10/10 → цель ≤4/10

**Exit criteria:** G2 PASS: по восемь фиксированных seed для двух заранее выбранных поддерживаемых жанров (например, Techno и Dub; выбор записать до прогона). Из 16 последовательностей минимум 12 проходят три проверки: related DEVELOPMENT, контраст BREAK, узнаваемый RETURN, при этом ≥6/8 в каждом жанре; минимум два из трёх слепых оценщиков подтверждают результат. Canonical event diff должен показывать структурные изменения, не только звук/FX. Зафиксировать каждый отказ и число ручных операций по доведению до результата.

**Evidence:** manifest seed/genre/BPM/engine SHA, 16 MIDI/event dumps, level-matched и timbre-normalized аудио, blind ratings, Song bar map, негативные примеры. Старый M0-A с одним неслепым слушателем — baseline, не PASS.

**GO:** музыкальный результат воспроизводим, ограничение Acid/House явно задокументировано. **STOP:** 16 тактов собраны только ручным исправлением каждого такта, звучат как одно и то же или результат подбирался повторными seed после прослушивания. Новые phrase laws запрещены в этой волне: честно зафиксировать FAIL и отдельно переоценить scope.

### R3. Слабый встроенный звук — 10/10 → цель ≤4/10

**Exit criteria:** G4 PASS и DSP #496 hardware closure. TB303: минимум два слышимо разных пригодных басовых пресета; WAVEMORPH: минимум два различимых lead/bass пресета; барабаны не маскируют обе синтезаторные партии в эталонном миксе. При воспроизведении 10-минутных эталонов нет непреднамеренных щелчков, clipping, NoteOff-зависаний и новых underruns. Для исправленных DSP участков провести 11 существующих слепых A/B пар при сопоставимом уровне; сохранить голоса «лучше/хуже/равно» без подбора результатов.

**Evidence:** WAV до/после, уровни, таблица слушателей, speaker-vs-jack, TB303 filter impulse/retrigger test, 156 renderer cases, Cardputer CPU/heap/largest/click trace, физические Save/Load/switch/release. Software PASS #496 ≠ hardware PASS.

**GO:** пригодное preview без увеличения количества движков. **STOP:** изменены глобальный gain, sample rate, engine count или scheduler без доказанной необходимости; DSP-кандидат хуже стабильной #495 — вернуться к #495 и исправлять дефект точечно.

### R4. UX понятен преимущественно автору — 10/10 → цель ≤4/10

**Exit criteria:** G1 + G7 PASS; для пути G→TAKE→D→Undo→Save известны медиана времени, число клавиш, переходов, обращений к Help, число отказов и причины; 3/3 участника выполняют сценарий без устных подсказок. При каждом типизированном отказе экран сообщает музыканту что сделать дальше, не внутренние P-level/owner/receipt детали.

**Evidence:** три независимых видео с секундомером и листом заданий, event log ввода, компактный UX blocker report (симптом, частота, фикс), повторный слепой прогон после исправлений.

**GO:** минимальные правки существующих labels/defaults/навигации/Help. **STOP:** участник зависает на скрытом действии, получает «успех» при неуспехе или требуется новая экспертная страница, чтобы завершить базовый путь.

### R5. Нет честного определения «готово» — 10/10 → цель ≤3/10

**Exit criteria:** опубликован exact-SHA release manifest; все шесть автономных G-gates PASS и runtime gate PASS; G5 «REAPER» = DEFERRED; список известных ограничений, включая Acid/House DEVELOP и pruned WAV Sampler/Tape, указан пользователю; independent reviewer подписал матрицу доказательств. Ни один релиз не маркируется полным MIDI-first acceptance до будущего G5.

**Evidence:** acceptance-matrix.md, BIN SHA, тестовые артефакты, release notes, checklist подписей, known limitations.

**GO:** автономный release candidate или STANDALONE ACCEPTED. **STOP:** 5/6 либо формулировка «готово» основана на количестве функций, host PASS или личном подтверждении «кажется работает».

### R6. Ограничения Cardputer диктуют музыкальный дизайн — 9/10 → цель ≤4/10

**Exit criteria:** G1/G2/G4/G7 выполняются на физическом Cardputer, без REAPER/компьютера. По сравнению с #495 выполнен paired benchmark для #496: static DRAM ≤191 488 Б; отсутствуют новые underruns/heap leaks; измерены free heap, largest block, stack high-water в cold start, generation, 16B PLAY, Song/Undo, Save/Load и STOP. Quiet heap/largest ухудшились не более чем на 1 КиБ каждый в сопоставимых прогонах (иначе классифицировать и отдельно согласовывать); 30 минут рабочего прогона без watchdog/panic/underrun. Модель музыкальных событий host и hardware совпадает для фиксированных seed.

**Evidence:** парные 495/496 PERF logs, точные артефакт-хеши, CPU block-time p50/p95/p99, minimum heap/largest, таймлайн музыкальных действий и снимки UI.

**GO:** Cardputer служит работоспособным портативным фасадом ядра. **STOP:** ради этой платформы искажаются жанровые/гармонические правила, скрыто отбрасываются ноты или нужна новая аппаратная архитектура. Вопрос миграции отдельно, без реализации в этом цикле.

### R7. Архитектура слишком сложна для сопровождения — 9/10 → цель ≤4/10

**Exit criteria:** владельцы musical events, runtime transport, MIDI NoteOff, persistence, working/canonical и Undo задокументированы в одной компактной owner map; 0 новых runtime owners/очередей/дублирующих источников истины; 3 последующих багфикса ограничены принадлежащими им подсистемами, с воспроизводимой RED→GREEN проверкой и без массовых переработок соседних модулей. Нет свежих случаев, когда два агента меняют одного владельца одновременно.

**Evidence:** owner map (одна страница), diff/stat и карта затронутых subsystems для трёх PR, independent boundary review, A/B compatibility.

**GO:** изменения локальны и не добавляют архитектуру. **STOP:** исправление требует новых обобщений/слоёв либо >2 несвязанных владельцев без доказанной первопричины — сначала выделить минимальный дефект и решение review-board.

### R8. Сохранению нельзя доверять — 9/10 → цель ≤4/10

**Exit criteria:** G6 PASS, включая A+B 8B, Song refs, HGS, patch parameters, Save As/New/Clear, три холодных рестарта и две отрицательные проверки SD (отсутствует/ошибка чтения или записи). На ошибке Load текущий canonical project не должен повреждаться; сообщения об успехе только после подтверждённой операции. Отложенная публикация Scene после final filter acknowledgement — известная граница: попытка сбоя на этом пути либо должна подтвердить безопасное поведение, либо дать узкий fix. Power-cut atomicity отдельно пометить UNVERIFIED, если не тестировали.

**Evidence:** до/после hashes canonical events и параметров, SD failure injection, hardware serial/video, реальный Load с отличающимся предыдущим проектом.

**GO:** данные не теряются в определённых сценариях. **STOP:** любое ложное Save success, потерянный такт, stale Song ref или частично опубликованная сцена при неуспешном Load.

### R9. AI ускоряет наращивание сложности, а не поставку продукта — 9/10 → цель ≤4/10

**Exit criteria:** одна матрица задач, одна integration owner, одна зафиксированная база для каждого checkpoint; агенты работают в изолированных worktree и не меняют общие owners одновременно; в каждом из трёх следующих PR есть problem statement, scope/exclusions, exact base/head, тестовый RED, GREEN, hardware boundary и доказательство пользовательского улучшения; 0 автоматических merge и 0 feature-creep изменений.

**Evidence:** три карточки PR с independent review, scope diff audit, список отвергнутых неподходящих изменений, verified HEAD + build hashes.

**GO:** AI реализует утверждённые исправления в фиксированных границах. **STOP:** агент сам расширяет продукт, изменяет release gate после FAIL, объявляет непроверенный hardware PASS или объединяет незавершённые ветки.

## 4. Последовательность без создания новых функций

- **W0 — Recovery и freeze:** подтвердить эксклюзивный USB доступ. При неясном текущем образе восстановить ранее принятый BIN #495 (`b5a6a0e3dc8ea6604a20f7022ff548cbca2209d59bf4797ec8ac3c4fe45841e3`), проверить хеш, boot и звук; только после этого проверять #496. Зафиксировать exact SHA и freeze whitelist. Не сливать #494/#495/#496 автоматически.
- **W1 — Foundation:** G1, G3, G6 на #495; проверить память, cold boot, SD-failure. Эти результаты — контрольная группа.
- **W2 — DSP qualification:** установить и проверить #496 при безопасном USB ownership; выполнить G4, paired PERF и Sound A/B. При неудаче — откат к #495, а не блокировка всей музыки ради DSP.
- **W3 — Musical qualification:** G2 на итоговом кандидате, фиксированные seed/жанры, host canonical diff и слепое прослушивание. Проверить, что 16B действительно получены штатным workflow, а не созданной вручную демонстрацией под результат.
- **W4 — User qualification:** G7 с тремя независимыми участниками; только узкие UX-багфиксы и повторный тест.
- **W5 — Independent review:** 6/6 + runtime gate, release manifest, known limitations и 9 закрывающих risk records. Допуск — только по exact BIN и SHA.

## 5. Универсальный формат evidence и аудита

На каждый сценарий сохранить в `docs/acceptance/critical-review/`:

- `manifest.json`: HEAD SHA, BIN SHA-256, FQBN/flags, Cardputer board revision, test date, operator;
- `gate-GN.md`: precondition, действия, expected/actual, PASS/FAIL, обоснование;
- исходные MIDI/WAV и canonical-event hashes (когда уместно), независимо от выбранных тембров;
- `perf.csv`/serial: free heap, min free, largest block, CPU, stack high-water, underrun, panic/reboot;
- видео либо последовательность событий UX (G1/G7) и обезличенные оценки слепого прослушивания (G2/G4);
- diff/commit связанного узкого исправления и RED→GREEN regression;
- explicit **NOT TESTED** там, где данных нет.

## 6. Что делать при FAIL

| Не проходит | Разрешённая реакция | Запрещённая реакция |
|---|---|---|
| G1/G7 | уменьшить навигационную сложность существующего пути, уточнить текст и дефолты | добавить новую страницу или командную систему |
| G2 | найти дефект текущего DEVELOP/FORM/event realization; зафиксировать границу жанров | вводить новую гармоническую модель или менять seed post hoc |
| G3/G6 | восстановить owner/Undo/persistence lifecycle, воспроизвести fail | переписать весь Scene/Material storage |
| G4 | локальный DSP bugfix, корректный gain staging, revert #496 при необходимости | новый synth engine, повышение sample rate всего проекта |
| Runtime | profiling, удалить подтверждённую неактивную нагрузку, исправить lock/alloc bug | без приёмки выбрасывать TempoDelay или менять SDK USB |
| G5 | держать DEFERRED и сохранить нынешние MIDI contracts | объявить REAPER готовым по старому SEQTRAK тесту |
