# 0.9.11 A2 Canonical Material Operation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build one causal Pattern/material -> durable Melody -> explicit resolution -> prepared NEXT -> confirmed ACTIVE vertical slice without redesigning the existing M3/M4 runtime or expanding 0.9.11 into Scenes/Song.

**Architecture:** Keep A1's existing bounded `MaterialAddress` and verified `MelodyPromotion` durability primitive. Add only the missing control-side contracts: explicit resolution status/version token, one concrete material application operation with stale-request protection, and an adapter into the existing M3/M4 publication path. The operation distinguishes durable publication from audible activation and never converts unresolved state into Pattern implicitly.

**Tech Stack:** C++17 embedded/host tests, existing GroovePuter Scene/Pattern/Phrase runtime, MelodyStore/MelodyPromotion, GitHub Actions, Cardputer ADV memory gates.

**Spec:** `docs/architecture/0.9.11/0_9_11_SHARED_CONTRACTS.md` and `docs/architecture/0.9.11/0_9_11_RELEASE_SCOPE_FREEZE.md`

## Global Constraints

- `MaterialAddress` is a project-relative coordinate, not object identity.
- `UNKNOWN`, `NOT_RESIDENT`, `MISSING_PAYLOAD`, `CORRUPT_PAYLOAD`, and `INVALID_ADDRESS` must not resolve as Pattern.
- Durable publication and audible activation are distinct success boundaries.
- A stale preparation must not become NEXT after source/project/intent changes.
- Existing M3/M4 ACTIVE/NEXT and note-lifetime ownership remain authoritative.
- No filesystem, allocation, or waits in the audio activation path.
- No Scenes, Song, MAKE UNIQUE, Scale Lock, DEVELOP, rich take history, or mid-bar audition in A2.
- Do not rebuild A1's verified `write -> readback/decode/compare -> rename -> descriptor-last` persistence sequence.
