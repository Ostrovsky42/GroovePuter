# GroovePuter 0.9.11 M-WORKING Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to execute this plan task-by-task. Do not collapse RED and GREEN into one opaque change.

**Goal:** Implement the approved M-WORKING architecture so Pattern and Melody edits operate on an ephemeral, lossless WORKING candidate while ACCEPTED canonical material remains unchanged, without increasing Cardputer static DRAM.

**Architecture:** Reuse the already-paid per-voice `currentPhrase_` 1284-byte storage as an untagged representation-aware `WorkingMaterialStorage` that can hold either a lossless `SynthPattern` or a `RuntimeSynthEventBuffer`. The active/sounding representation remains derived from the existing `ActiveMaterial.kind` / sequenced-source authority rather than a new dirty/tag owner. Pattern runtime remains a projection of the Working `SynthPattern`; Melody playback continues to use the Working event buffer. Undo/Redo mutates WORKING only. DISCARD re-resolves ACCEPTED. Pattern→Melody migration occurs inside WORKING and is not acceptance.

**Tech Stack:** C++17, SDL host harness, existing `MiniAcid`, `RuntimePatternEventBank`, `RuntimePhraseEdit`, `UndoOwner`, A2 `MaterialAddress`/`MaterialResolution`/`MaterialVersionToken`, GitHub Actions, Arduino/Cardputer ADV build and ELF DRAM gate.

**Spec:** `docs/superpowers/specs/2026-09-11-0.9.11-m-working-design.md`

## Global constraints

- Base implementation branch starts from exact approved design HEAD `b71e3d8825c63ecc27f34aa4a0aafdd2f872ff42`.
- Preserve a reproducible RED checkpoint before production code. Create `feature/20260911-0.9.11-m-working-red` from the design HEAD; GREEN may continue on a sibling `feature/20260911-0.9.11-m-working-green` from the exact RED commit.
- No final durable ACCEPT in this checkpoint. M-ACCEPT remains later work.
- No Take history, candidate ring, Scenes redesign, Song redesign, QWERTYUI, nanoKEY2, DEVELOP, UI-V2, or genre/G4 work.
- No second full Pattern/Melody working copy, no second Undo owner, no page-owned domain buffer, no hidden persistence mutation.
- Do not use `RuntimePatternEventBuffer` as a reversible Pattern owner.
- Do not add a permanent `workingDirty` flag. Modified state is derived from representation + exact-content token.
- Do not add filesystem I/O, JSON work, allocation, or material resolution to audio callbacks.
- Existing ACTIVE/NEXT publication remains authoritative.
- Static DRAM must not increase beyond the release gate. Current gate is 191488 bytes; the known C0 fixed baseline was 191472 bytes.
- Existing source/UI tests that encode the old persistent Pattern-edit contract may be updated only where the approved ownership model intentionally changes. Keep all unrelated assertions intact.
- If any STOP condition from the approved spec is proven, stop before broadening production scope and report the exact conflict.

### Step 2.2 — Implement the untagged storage owner

Use a union with explicit active-member construction. Do not add a representation byte inside this object; the authoritative representation is external (`ActiveMaterial.kind` / sequenced source) and will be guarded by tests.

Target shape:

```cpp
#pragma once

#include <new>
#include <type_traits>

#include "../../scenes.h"
#include "../phrase/runtime_synth_events.h"

namespace GroovePuterMaterial {

class WorkingMaterialStorage {
 public:
  WorkingMaterialStorage() { storeMelody({}); }
  ~WorkingMaterialStorage() = default;

  void storePattern(const SynthPattern& pattern) {
    new (&payload_.pattern) SynthPattern(pattern);
  }

  void storeMelody(const PhraseRuntime::RuntimeSynthEventBuffer& melody) {
    new (&payload_.melody) PhraseRuntime::RuntimeSynthEventBuffer(melody);
  }

  SynthPattern& pattern() { return payload_.pattern; }
  const SynthPattern& pattern() const { return payload_.pattern; }

  PhraseRuntime::RuntimeSynthEventBuffer& melody() { return payload_.melody; }
  const PhraseRuntime::RuntimeSynthEventBuffer& melody() const {
    return payload_.melody;
  }

 private:
  union Payload {
    SynthPattern pattern;
    PhraseRuntime::RuntimeSynthEventBuffer melody;
    Payload() {}
    ~Payload() {}
  } payload_;
};

static_assert(std::is_trivially_copyable<SynthPattern>::value,
              "Pattern working storage requires trivially-copyable Pattern");
static_assert(std::is_trivially_copyable<
                  PhraseRuntime::RuntimeSynthEventBuffer>::value,
              "Melody working storage requires trivially-copyable runtime buffer");
static_assert(sizeof(WorkingMaterialStorage) <=
                  sizeof(PhraseRuntime::RuntimeSynthEventBuffer),
              "M-WORKING must reuse the currentPhrase_ footprint");

}  // namespace GroovePuterMaterial
```

If the current compiler rejects the union-lifetime approach, use `std::aligned_storage` plus placement construction, but preserve the same size bound and no tag. Do not switch to heap allocation merely to simplify C++ lifetime handling.
