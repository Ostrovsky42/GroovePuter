# Кривая энергии: аранжировка жестом (план)

Статус: план, код не начат. Направление 2 из обсуждения 2026-10-08.
Пара к GRAB (`2026-10-08-0918-grab-from-midi-player.md`).

## Зачем

Сейчас песня собирается ячейка за ячейкой. Корпус референсов
(`2026-10-08-0918-corpus-vs-generator.md`) показал: развитие в этих жанрах
живёт на уровне аранжировки — голоса входят и выходят, лид молчит такт и
отвечает, — а не в смене нот. Кривая энергии даёт один жест на форму
песни: нарисовал интро → разгон → дроп → брейк → дроп, нажал — получил Song.

Критерий успеха (владелец, на слух): за 30 секунд с кривой получается
минута, которую интереснее слушать, чем A A DEV A BRK из P0
(`p0_minute`), и быстрее, чем собрать её руками.

## Опора на то, что уже есть

- **Пустая ячейка Song = дорожка молчит в этом такте**
  (`miniacid_engine.cpp:4220` синты, `:4272` барабаны). Значит, входы и
  выходы голосов выражаются существующей моделью Song без нового формата.
- P0 cycle (`GeneratedPhraseSong::generateCycle`): A → DEVELOP → BREAK,
  один Undo, PendingNextBar live. Кривая — обобщение этого на N секций.
- Материалы A/B/Drums одного TAKE + варианты из GEN (LIVELY, NOTES).
- Mix C, Undo-owner для Song (`commitSongMutation`).

## Модель

- Кривая = до 8 секций, у каждой длина (4/8 тактов) и уровень энергии 0..4.
- Уровень → набор голосов и вариант материала:

| Энергия | Барабаны | Бас (A) | Лид (B) | Материал |
|---|---|---|---|---|
| 0 | — | — | лид или пусто | тишина / вступление |
| 1 | только хэт/перкуссия* | — | — | |
| 2 | полные | основной | — | |
| 3 | полные | основной | лид, редкий (CALM) | |
| 4 | полные | основной | лид, плотный (LIVELY) | дроп |

\* «только хэт» требует отдельного drum-слота с прорежённым паттерном —
это первый случай, когда нужен *новый* материал, а не пустая ячейка.

- **Переходы** (второй шаг): в последнем такте перед ростом энергии —
  подхват лида (PickupPhrase/LazyArp-подхват) или fill барабанов; перед
  падением — один такт без баса (паузу одной партии слышно как смысл).
- Тональность и гармония общие для всей песни (один TAKE), иначе это уже
  не аранжировка, а генерация разных треков.

## UI (240×135)

Отдельная вкладка в SONG или MATERIAL: 8 столбиков, высота = энергия.

- `Left/Right` — секция; `Up/Down` — энергия; `Fn+Left/Right` — длина
  секции 4/8; `G` — собрать Song по кривой (один Undo); `Space` — слушать.
- Пресеты-формы на цифрах: `1` BUILD (1-2-3-4-4), `2` DROP
  (2-3-4-1-4), `3` WAVE (2-4-2-4) — чтобы первый результат был за одно
  нажатие, а кривую уже можно править.
- Риск, который решает судьбу фичи: если рисовать кривую медленнее, чем
  собрать Song руками, она не нужна. Поэтому пресеты обязательны.

## Задачи

1. **Чистая функция (host, TDD).** `EnergyCurve` + `planArrangement(curve,
   materials) -> SongRows`: строки Song с ячейками или -1 по таблице выше.
   Тесты: уровни → ожидаемые пустые ячейки, длины секций, лимит 128 строк,
   кривая без барабанов, пустая кривая.
2. **Применение.** Запись строк через `commitSongMutation` одним Undo,
   с проверкой места и с отказом вместо усечения (как P0 cycle).
3. **Вариант лида для 3/4.** Использовать LIVELY CALM/LIVELY: два
   слота B (если свободны) или один B на уровне 4 и пусто на 3 — решить по
   слотам; без новых слотов первый срез делает 3 = 4 без лида.
4. **UI вкладки + пресеты**, SDL-скриншоты для проверки раскладки.
5. **Рендер для прослушивания:** `takerender`-подобный инструмент, минута
   по кривой BUILD и DROP для 2–3 жанров (Rave, Synthwave, LoFi) против
   `p0_minute`.
6. **Второй шаг:** переходы (подхват/fill/один такт без баса), уровень 1 с
   прорежёнными барабанами, фильтр по энергии.

## Открытые вопросы владельцу

## Предложения по открытым вопросам — 2026-10-09

Статус: рекомендации для обсуждения с владельцем, не разрешение на реализацию.
Это редактор формы аранжировки, поэтому он живёт во вкладке SONG: GRID / FORM.
MATERIAL остаётся местом выбора исходного TAKE и его вариантов. Кривая —
параметры построения обычного Song, не второй независимый проигрыватель.
После применения слышимый результат целиком определяется строками Song;
ручная правка GRID не должна автоматически перезаписываться кривой.

### Куда записывать

Первый срез: вставить после выбранной строки, сохранив существующую песню.
До применения показать диапазон, число строк и требуемые свободные слоты.
Если места нет — отказ без частичных изменений. Один Undo возвращает весь
результат применения. Для пустой песни отдельно определить заполнение с
первой строки, чтобы не создавать лишний пустой такт.

Замена целого Song — отдельный явно выбранный режим REPLACE с предварительным
показом объёма замены; не обычное действие G. Альтернатива — построить в другом
Song A/B для сравнения, но лишь если это не затирает занятую песню.
На первом шаге достаточно одного INSERT: меньше режимов и проще проверить.
Если создаются новые варианты в слотах, одного Song Undo недостаточно:
нужен существующий общий владелец Undo для материалов и Song либо заранее
подготовленные, уже сохранённые материалы. Не обещать атомарность только
через commitSongMutation.

### Уровни энергии

В первом срезе сохранить честную шкалу 0..4 и формы BUILD/DROP/WAVE.
Уровень 0 = все голоса молчат; лидовое вступление задаётся отдельно, иначе
нулевая энергия непредсказуема. Уровень 1 требует заранее подготовленного
перкуссионного варианта, 2 = drums+bass, 3 = drums+bass+редкий лид,
4 = drums+bass+полный лид. Не выдавать одинаковые 3/4 за разные уровни.

Для первого прототипа редкий лид уровня 3 можно выразить чередованием
пустых/заполненных ячеек, не генерируя новый лид. Но это надо слушать:
после паузы мелодия может активироваться с начала, поэтому это повторный
вход фразы, а не гарантированное продолжение прежнего такта.
Если перкуссионного варианта нет, BUILD требует его подготовки либо явно
отказывает; молчаливое превращение 1 в 2 ломает смысл кривой.

### Что ещё проверить до реализации

- Один TAKE гарантирует общий материал, но не фазу многотактовой гармонии.
  Смена слота, паузы и возвращение голоса должны быть проверены на реальном
  Song playback с 4/8-тактовыми мелодиями, а не только по индексам ячеек.
- 8 секций × максимум 8 тактов = 64 строки; технический лимит Song 128
  проверяется вместе с уже существующими строками при INSERT.
- Сравнение «интереснее за 30 секунд» проводить с ручной аранжировкой того
  же TAKE, темпа и инструментов; новый TAKE не должен маскировать слабую форму.
- Fn-стрелки проверить на устройстве: обработчик может получать уже
  преобразованные клавиши. Надпись в плане не доказывает достижимость chord.
- Семантика пустой ячейки должна быть закреплена тестом проигрывания,
  особенно после Melody: тишина, отсутствие старых NoteOn, корректные NoteOff.
