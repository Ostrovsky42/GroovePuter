# MIDI IN/OUT и nanoKEY2 Implementation Plan

> **For agentic workers:** Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax. Delegation requires explicit user authorization; this document does not authorize spawning agents.

**Goal:** nanoKEY2 и UART MIDI IN управляют общим движком аккордов/ARP/ритмов, а USB и UART OUT независимо доставляют результат.

**Architecture:** Один музыкальный timeline и PERFORM движок; отдельные input identities и endpoint delivery states. USB lifecycle, пользовательские маршруты и clock master имеют независимые состояния. Смена USB-роли в v1 применяется после reboot; attach/detach внутри роли автоматические.

**Tech Stack:** C++/Arduino на ESP32-S3 Cardputer ADV, существующий TinyUSB device, ESP-IDF USB Host API после аппаратного допуска, HardwareSerial, FreeRTOS, native C++ tests и SDL.

**Spec:** [Закреплённые контракты C01–C10](../../midi/2026-09-07-midi-io-contracts.md). Прочитать целиком перед реализацией.

## Global Constraints

- Release без PSRAM.
- DRAM gate 191488 не повышать ради прохождения.
- В audio callback запрещены allocation, USB/UART I/O и блокировки.
- Ровно один clock master: Internal, USB IN или UART IN.
- USB reject не задерживает UART. UART reject не повторяет доставленный USB NoteOn.
- `releaseMissingKeys()` освобождает только QWERTY.
- События предыдущего generation не могут попасть в новый сеанс.
- Raw echo/THRU отсутствует.

## Порядок и границы checkpoints

`P0 baseline → H0 hardware → P1 states → P2 outputs → P3 performance input → P4 UART RX → P5 USB RX → P6 settings/clock → H1 acceptance`.

H0 блокирует только обещание и реализацию production USB host; независимые
P1–P4 могут быть реализованы и проверены при отрицательном H0. P5 Host требует
H0 PASS. Каждый checkpoint — отдельный reviewable commit при выполнении плана;
не включать существующие чужие изменения и patch-файлы. Историю сохранять,
rebase запрещён. Само составление плана не включает commit или прошивку.

## P1. Чистая state machine и bounded ingress

**Files:** создать `midi_io_state.h`, `midi_input_event.h`, `midi_input_queue.h`
по карте, `tests/test_midi_io_state.cpp`, новый contract runner.

**Interfaces:** определить в namespace `GroovePuterMidi`:

```cpp
enum class InputSource : uint8_t { Qwerty, Usb, Uart };
enum class UsbRole : uint8_t { Off, Device, Host };
enum class InputKind : uint8_t { NoteOn, NoteOff, Sustain, AllNotesOff, AllSoundOff };
struct InputKey { InputSource source; uint32_t generation; uint8_t channel; uint8_t key; };
struct MidiInputEvent { InputKey id; InputKind kind; uint8_t velocity; uint32_t atMicros; };
```

State transitions возвращают команды для владельца ресурса, не выполняют I/O.
SPSC `tryPush(const MidiInputEvent&)` / `tryPop(MidiInputEvent&)` возвращают bool;
recovery flag потребляется control task независимо от очереди.

- [ ] Написать trace tests C01–C03/C07/C09: attach не меняет routes,
  waiting USB не отключает UART, generation меняется при detach/recovery,
  pending role не меняет active role до boot.
- [ ] Проверить насыщение 48 NoteOn slots: 16 release slots ещё доступны;
  после полного заполнения critical overflow устанавливает recovery flag.
- [ ] Реализовать модель и runner; проверить
  `bash tests/run_midi_io_contract_tests.sh state`.

Пример обязательного assertion для будущего test harness:

```cpp
// После полного заполнения очереди requestSourceRecovery не делает enqueue.
assert(queue.recoveryPending());
// После detach событие из прежнего поколения не допускается.
assert(event.id.generation != activeGeneration);
```

**Exit:** все переходы C07 покрыты; ни модель, ни parser не включают Arduino.

- [ ] Реализовать RX bounded drain и driver overflow recovery; не использовать

- [ ] Запустить `bash tests/run_midi_io_contract_tests.sh uart` и output tests.

Байтовый golden пример (channel 0):


## Coverage и rollback

| Контракт | Checkpoints | Обязательное доказательство |
|---|---|---|
| C01 роли/порты | H0,P1,P5 | Реальные descriptors + state traces |
| C02 host/power | H0,P5,P6 | VBUS, core compile, reboot role |
| C03 routes | P1,P2,P6 | Attach не меняет настройки |
| C04 input | P3,P4,P5 | MIDI и QWERTY sink traces |
| C05 cleanup | P3,H1 | Sustain/latch detach + shared pitch |
| C06 delivery | P2,H1 | Reject matrix и deferred Off ordering |
| C07 transitions | P1,P2,P5,P6 | Generations + reconnect без backlog |
| C08 clock | P0,P4,P5,P6,H1 | Один master, timeout baseline, no echo |
| C09 ресурсы | P1,P2,H0,H1 | Queue pressure, ELF и runtime minima |
| C10 UX/evidence | P6,H1 | Honest status и hardware report |

При провале checkpoint не маскировать его увеличением памяти/таймаутов или
ослаблением теста. Вернуться к последнему прошедшему checkpoint обычным revert
его собственных commits, сохранив пользовательские изменения. Host профиль
