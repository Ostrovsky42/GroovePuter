# MIDI IN/OUT и nanoKEY2 — Implementation Plan v3: memory gates

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax. Выполнять последовательно в существующем worktree; этот план не разрешает автоматическую делегацию.

**Goal:** nanoKEY2 через USB-C играет общим CHORD/ARP/rhythm движком GroovePuter; результат независимо доставляется на UART/USB, без чужих NoteOff и зависших нот при смене подключений.

**Architecture:** Один PERFORM engine и музыкальный timeline. Отдельные input identities, поколения input/USB session/output, очереди и wire ownership каждого выхода. Роль USB задаётся на следующий boot, attach/detach внутри роли автоматические.

**Tech Stack:** C++17/native tests, Arduino/M5Stack ESP32 core 3.2.2, установленный ESP-IDF USB Host API, существующий TinyUSB Device, FreeRTOS, UART1, SDL.

**Spec:** [Контракты v2 C01–C11](../../midi/2026-09-07-midi-io-contracts.md). Прочитать целиком. Эта редакция заменяет прежний план v1 из основного checkout.

## Global Constraints

- Release без PSRAM.
- DRAM gate 191488 не повышать ради прохождения.
- В audio callback запрещены allocation, USB/UART I/O и блокировки.
- Ровно один clock master: Internal, USB IN или UART IN.
- USB reject не задерживает UART. UART reject не повторяет доставленный USB NoteOn.
- `releaseMissingKeys()` освобождает только QWERTY.
- События предыдущего generation не могут попасть в новый сеанс.
- Raw echo/THRU отсутствует.
- Составление этого плана не включает реализацию, прошивку, commit или merge.
