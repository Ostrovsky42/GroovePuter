# 0.9.14 и 0.9.15: план работ на трое суток

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Реализацию вести в отдельном worktree; этот документ сам по себе не запускает реализацию.

**Goal:** За 72 часа довести согласованный объём 0.9.14 до кандидата с доказательствами и проверить 0.9.15 с внешней MIDI-клавиатурой в одной прошивке, переключающей USB Host/Device через сохранение настройки и перезагрузку.

**Architecture:** Сначала изолировать базу и проверить ограничения USB/RAM, затем закончить музыкальный и UI-контракт 0.9.14. USB Host подключить к существующим MIDI ingress, PERFORMANCE и выходам; активировать только один USB-стек за загрузку. Настройка роли относится к устройству, музыкальные параметры — к проекту.

**Tech Stack:** C++17, Cardputer ADV / ESP32-S3, Arduino M5Stack core, FreeRTOS, ESP-IDF USB Host, TinyUSB Device, SDL2, существующие host/build-гейты. Установленный core при подготовке плана: M5Stack 3.2.2; при исполнении записать точную версию и конфигурацию.

## Global Constraints

- База: `b5cf8e5b86fe37f5cf71c43e20f0d94bc3df5d33`. Общий worktree содержит чужие незавершённые изменения; собирать и проверять кандидатов только в отдельном worktree.
- Установленный бинарник, чистый коммит и диагностический образ — три разные идентичности. Без подтверждённого происхождения нельзя приписывать телеметрию коммиту.
- Сохранить историю; без rebase, массового merge старой MIDI-ветки и очистки общего дерева. Переносить только просмотренные изменения с установленным происхождением.
- Существующий статический предел `.dram0.data + .dram0.bss ≤ 191488 B` сохранить. Он не доказывает runtime-безопасность.
- Резерв внутренней памяти `max(16384 B, 2 × измеренный временный пик)` — выбранная политика допуска, не аппаратная гарантия. Проверять также крупнейший блок, стеки и совместную нагрузку.
- Одна прошивка: роль USB сохраняется → применяется после перезагрузки. Две разные прошивки Host/Device не удовлетворяют этой цели.
- Перезагрузка — согласованная граница продукта; не утверждать, что это единственный технически возможный способ. В этом объёме live-смена USB-стека не требуется.
- Host обслуживает USB MIDI-клавиатуру; Device подключается к ПК/другому USB-host. Под словом «клиент» в интерфейсе понимается Device, а не внутренний client USB Host Library.
- Автоматическое переподключение клавиатуры в активном Host обязательно. Отсутствие трафика не меняет роль, маршруты или владельца Clock.
- Сохранить единый музыкальный движок и владельцев MIDI-нот/выходов. USB-вызовы, файловый I/O, ожидание UI и новые allocations не должны попадать в аудиопуть.
- Загрузка проекта не меняет роль USB и не вызывает перезагрузку. Отмена выбора не меняет сохранённую настройку.
- Для аппаратных замеров заранее выделить окно работы с владельцем устройства: кандидат сначала собрать, показать хеш и назначение, затем прошивать по явному запросу. Публикация/пуш не входят в этот план.

## Review Focus

1. Сборка случайно захватила общие dirty-файлы → идентичность исходников и артефактов проверяется в Task 1.
2. Host укладывается без нагрузки, но генерация/Load исчерпывают RAM → совместные пики и отдельные стеки проверяются в Tasks 2, 4, 7.
3. Device USB запущен core до `setup()` → ранний выбор и одна прошивка проверяются в Task 2 и Task 6.
4. Потерян NoteOff или в очереди остались ноты прошлого подключения → overflow, disconnect и session fencing проверяются в Task 7.
5. Экран обещает отмену, замену или перезапуск, которые работают иначе → настоящие scancode/modifiers и состояния проверяются в Tasks 3, 6.

Запускать из isolated worktree. Сейчас планирование не запускает эти команды.

| P0 cycle | `bash tests/run_0_9_14_p0_cycle_tests.sh` |

| Commit / whitespace | `git diff --check`, `git status --short`, `git rev-parse HEAD HEAD^{tree}` |

Runtime-инструментатор может не совпасть с anchors чистой базы: сначала проверить его применимость в временной копии; failed anchor — явная ошибка инструмента, не повод копировать dirty production-файлы. Проба требует собственных hashes и FQBN; normal Device-профиль не является Host budget.

SDL gate в `validate_gf2_targets.sh` доказывает сборку, не визуальный сценарий. Сам эмулятор запускать из `mktemp -d`, окно искать по PID и сверять PID; сравнивать кадры/состояния отдельно. Fixtures и temporary seeding только в изоляции, после изменения header — гарантировать пересборку.

## Решения при нехватке времени

- **Память не проходит:** 0.9.15 получает BLOCKED с alloc/caps/пиком/крупнейшим блоком и результатом ограниченной оптимизации. 0.9.14 продолжается независимо.
- **Нельзя выбрать роль до USB startup в одном бинарнике:** фиксируется startup blocker. Отдельные Host/Device builds разрешены как диагностические, цель пользователя этим не закрыта.
- **Нет устройства/согласованной прошивки:** software/build проверки продолжаются; hardware gate остаётся UNAVAILABLE. Отсутствие устройства не PASS.
- **Осталось менее 12 часов:** новых features не добавлять; сохранить воспроизводимые кандидаты и закончить проверку.
- **P1 variants / кнопка P на синтах:** открытые продуктовые решения; не увеличивать критический путь по умолчанию.

## Технические основания

Reboot-role — согласованный продуктовый выбор. Особенности PHY, async callbacks, управления ресурсами и uninstall проверять по [официальной документации ESP-IDF USB Host v5.4](https://docs.espressif.com/projects/esp-idf/en/v5.4/esp32s3/api-reference/peripherals/usb_host.html) и локальному core 3.2.2, а не по API latest другой версии. USB Host event handlers могут блокировать, поэтому их выполнение относится к отдельному USB-owner, а не к AudioTask; освобождение библиотеки требует завершённого освобождения clients/devices. [ESP-IDF USB Host](https://docs.espressif.com/projects/esp-idf/en/v5.4/esp32s3/api-reference/peripherals/usb_host.html)
