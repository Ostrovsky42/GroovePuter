# LOOP HOLD, EVOLVE и адаптивный DUET

Статус: конкретизация выбранных пользователем функций перед реализацией.

## Поведение

### HOLD
Новая строка HOLD в PERFORMANCE TOOLS > INPUT: OFF/ON. Активна в LOOP после первой захваченной фразы. ON сохраняет исходный материал LOOP: новые ноты человека звучат, но не заменяют петлю. Позиция петли не сбрасывается. OFF разрешает замену со следующего полностью захваченного окна; незавершённый ввод из периода HOLD не становится новой петлёй. При BARS, OFF, новой эпохе транспорта и выходе из LOOP HOLD сбрасывается. X выключает PARTNER, как сейчас.

HOLD сохраняет исходный мотив. Для точного повторения результата используется EVOLVE=0. Не вводить отдельный глобальный MIDI-перехват или запись аудио.

### EVOLVE
Новая строка EVOLVE: 0..3, активна в LOOP. По умолчанию 1. Все варианты вычисляются заново от сохранённого оригинала; изменения не накапливаются необратимо.

- 0: повтор исходных высот/ритма/velocity в пределах существующих диапазона MIDI и доступного окна с DELAY; без жанрового окончания и гармонической замены. Гарантировать точный повтор для валидных нот существующего диапазона 24..71 и delay=0; для delay=1 сохранять существующее ограничение конца окна.
- 1: исходный ритм, существующая гармонизация и жанровое окончание; без чередования SHORT_REPLY/DEVELOP.
- 2: текущая политика чередования ECHO/DEVELOP/SHORT_REPLY с гармонизацией.
- 3: как 2, плюс дополнительные допустимые сдвиги хвоста на одну шестнадцатую; первые две атаки сохраняются. Без добавления новых нот.

При смене EVOLVE текущий ответ доигрывает; новое значение применяется на следующей границе окна. Материал петли сохраняется. Не менять ANSWER этим параметром.

### DUET по умолчанию
На основе плотности последней завершённой фразы выбирается ответ: при >=8 нотах на такт оставлять до ceil(N/2) нот; при меньшей плотности использовать обычный ответ. Новые атаки во время ответа не отменяют его. Это реакция на последнее окно игры, а не обещание мгновенного анализа плотности внутри текущей доли. Не добавлять молчание целыми окнами и не подавлять живую игру. Настройка по умолчанию включена; отдельное меню на первом этапе не нужно.

## Код
- call_response_listener.h: HOLD, EVOLVE, применение захвата только вне HOLD, сбросы.
- call_response_development.h: чистый выбор преобразований и адаптивное сокращение DUET.
- GroovePuter.ino: общий путь планирования для режимов; EVOLVE=0 обходит гармонические изменения.
- perform_page.cpp/.h: две строки, подсказки, неактивное состояние вне LOOP; существующий скролл.
- tests/test_cr_partner_settings.cpp, test_cr_response_cancel.cpp, test_cr_development.cpp: поведение HOLD, EVOLVE, два такта, одновременная игра, сбросы и границы окна.

## Приёмка
HOLD не меняет оригинал при новой игре, RELEASE не подхватывает старый ввод периода HOLD. EVOLVE=0 возвращает исходный мотив после любой серии изменений. При EVOLVE=3 остаются строгий порядок атак и положительные длины, ответ укладывается в окно. Для LOOP 1/2 такта проверить воспроизведение и смену BARS. DUET сокращает плотный ввод, продолжает звучать при одновременной игре. X гасит ответ и не оставляет запланированных нот. Shared-note MIDI ownership сохраняет ноту другого владельца.

Проверки: полный run_smart_play_tests.sh, UI-регрессии, SMF-cleanup, CDC/MIDI-only сборки и DRAM gate. Автотесты не подтверждают музыкальную оценку: отдельно прослушать одни и те же фразы до/после. Новые настройки сессионные, как существующие PARTNER.

## Ограничения
Без heap в MIDI/музыкальном пути, без увеличения capacity=16. Бюджет DRAM 191488 байт; текущая CDC-сборка 185396 байт. Не обещать бесшовность USB-переподключения без аппаратного теста. Никаких новых уровней меню, нейросетей или записи на SD.
