# 0.9.11 A2 — Identity-Bound Material Resolution RED

## Root

This checkpoint starts from the closed MaterialId G2 root:

`da9b2749a2ad5d4b3ed9ceade169800de9613e6f`

The A2-A donor is research/implementation evidence only. It must not be merged or cherry-picked as a whole because its resolver accepts a naked `MaterialAddress` and therefore predates the independent `MaterialId` contract.

## Problem

`MaterialAddress` answers **where to look**. It cannot prove **which logical material is there** because the address may be reused.

The old A2-A donor shape:

```cpp
resolveMaterial(..., MaterialAddress address, ...)
```

can resolve `N@A` for a stale caller that still means `M@A` after the slot is replaced.

That violates the already-proven MaterialId law:

```text
M@A idM -> replace -> N@A idN
idM != idN
stale {A,idM} must not resolve N
```

## Required boundary

Identity-sensitive canonical resolution consumes:

```cpp
MaterialReference { MaterialAddress address; MaterialId id; }
```

not a naked address.

Resolution must validate, in order:

1. address validity / residency;
2. reference validity (`id != 0`);
3. resident slot identity matches `{address,id}`;
4. only then inspect representation/payload and compute `MaterialVersionToken`.

`MaterialVersionToken` is exact-state evidence, not identity evidence. Same content/version cannot rescue a stale reference.

## Required statuses

This RED freezes two identity failures distinct from storage/residency failures:

- `InvalidReference`: the supplied reference has no valid MaterialId (including legacy/unassigned id `0`);
- `IdentityMismatch`: the address is resident, but its current MaterialId is not the referenced MaterialId.

Existing A2 resolution states such as `NotResident`, `MissingPayload`, `CorruptPayload`, and `StorageUnavailable` remain conceptually separate.

## Adversarial witness

At resident address `A`:

1. create logical `M` with `idM`;
2. capture `stale = {A,idM}`;
3. replace it with logical `N` carrying `idN` while leaving Pattern bytes unchanged;
4. resolving `stale` must return `IdentityMismatch` and expose no version;
5. resolving `{A,idN}` may resolve the current Pattern and expose its exact version;
6. resolving `{A,0}` must return `InvalidReference` and expose no version.

The unchanged Pattern bytes are intentional: the witness proves content/version equality cannot substitute for MaterialId equality.
