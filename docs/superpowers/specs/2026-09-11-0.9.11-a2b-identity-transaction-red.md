# GroovePuter 0.9.11 A2-B Identity-Bound Promotion RED

**Status:** TEST-ONLY RED

**Parent GREEN:** `730daa7d23f081123f34e122d6f85cfa17ee3158`

**Branch:** `feature/20260911-0.9.11-a2b-identity-transaction`

## Goal

Carry the A2 identity authority across the Pattern -> Melody mutation boundary.
A prepared candidate must not be publishable merely because its address still
maps to the same resident slot after that address has been reused by a different
`MaterialId`.

## Proven gap

A2 made resolution fail closed on stale `MaterialReference {address,id}` and
separated global durable location from resident runtime location. Promotion still
accepts only bare `MaterialAddress + residentSlot`.

That leaves an ABA/causality hole:

1. M owns address A and candidate M is prepared.
2. A is reused by N, so `{A,idM}` is stale.
3. Promotion is called with A and the reused resident slot.
4. Current production cannot observe `idM`, so it publishes candidate M and
   marks N's descriptor as Melody.

The RED witness uses global slot 21 -> resident slot 5 and proves exactly that
misbinding.

## Invariants

### A2B-PROMO-01 — MUTATION AUTHORITY IS A MATERIAL REFERENCE

Promotion must be authorized by the same `{address,id}` identity contract used
for resolution. Address equality alone is not authority to mutate.

### A2B-PROMO-02 — STALE REFERENCE FAILS BEFORE STORAGE MUTATION

If the current resident descriptor does not carry the referenced `MaterialId`,
promotion must fail before temp write, rename, final publication, or descriptor
kind mutation.

### A2B-PROMO-03 — EXISTING TRANSACTION ORDER REMAINS AUTHORITATIVE

For a live reference, preserve the existing M2b order:
encode -> temp write -> read-back/decode/semantic compare -> rename -> publish
resident kind last.

### A2B-PROMO-04 — GLOBAL STORAGE / RESIDENT RUNTIME REMAIN SEPARATE

Durable paths remain keyed by global `MaterialAddress`. Runtime descriptor
access remains keyed by the resident slot derived from that address.

## Explicitly out of scope

- Re-entrant or multi-threaded Scene mutation during filesystem callbacks.
- Power-loss recovery redesign or replacement/rollback journaling.
- Material lineage/version-history semantics.
- G4, Song orchestration, UI, MIDI, or hardware behavior.

## RED acceptance

The test-only checkpoint is valid only if exact-head CI reproduces:

`A2B_STALE_PROMOTION_RED: stale {address,idM} candidate was published after the resident identity changed to idN; idN was marked Melody with idM payload`

No production file may change in the RED commit.
