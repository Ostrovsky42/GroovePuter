Boot ordering in `GroovePuter.ino`: display init; I2S; audio task; delay buffers; SD; settings and MIDI dispatcher; encoder; engine; UI. Check preceding code and error paths in exact build before interpreting this as every dependency's complete allocation order. I2S/other boot failure can change path. SMF service initialization is deferred. The local UI acceptance overlay multiplies stack watermarks by `sizeof(StackType_t)` (`GroovePuter.ino:373–375`, dispatch helper `cardputer_usb_midi_transport.cpp:2159`); `docs/stages/CARDPUTER_MEMORY_RUNTIME_TELEMETRY.md` says pinned ESP-IDF watermarks are already bytes. Treat this as a **unit discrepancy requiring verification against pinned headers**; do not base reductions on overlay. The separate temporary-instrumented telemetry contract reports raw bytes.

Overlap matrix: active Scene, engine, audio buffers, MIDI queues and task stacks are live through playback; storage load and generation can be invoked while playback is active. Their concurrency with the pending generation/activation/undo state must be verified before any sharing. Serialization scratch may be logically idle outside load, but static residency persists. A call-site search cannot prove no reentry from callbacks, failure, USB or interrupts; no arena is authorized.
