# 0.9.9-E1 characterization baseline

This is evidence for the first checkpoint, not a consolidation proposal.

## Exact source facts

- `rhythm_realizer.cpp:addVariation()` invokes the existing variation passes
  for secondary and ghost additions. It does not invoke legacy trajectory drop,
  and the production realizer has no production `DROP`/`DISPLACE` operation.
- `bar_evolution.cpp:evolveRhythmPhrase()` selects a trajectory and applies the
  legacy trajectory/orchestration policy, including `dropOneStructuralEvent`
  where the selected trajectory requests reduction/break behavior.
- `phrase_evolution.cpp:evolveMultiBarPhrase()` calls `evolveRhythmPhrase()`.
  For eight bars it evolves two four-bar segments; the second segment receives
  the first segment identity and `phraseOrdinal + 1`.
- `strong_rhythm_live_bridge.cpp:regeneratePhraseAuditionWithProbe(MiniAcid&)`
  constructs the `PhraseEvolutionRequest`, calls `evolveMultiBarPhrase()`, and
  then materializes each evolved bar through `materializeEvolvedDrumBar()`.

## Ownership/evidence map (pre-consolidation)

The executable host corpus in `tests/test_e1_runtime_characterization.cpp`
uses fixed catalog identities, seeds, and generation ordinals. It prints stable
before/after masks for canonical versus P2 realization, locks the observed
semantic diff in `tests/goldens/e1_runtime_characterization.golden`, and checks
byte-equivalent reruns. The same corpus exercises 2-, 4-, and 8-bar phrase
evolution; the 8-bar result reports two four-bar segments and deterministic
trajectory/context continuation.

| semantic | production rhythm realizer | legacy bar evolution | phrase evolution |
|---|---|---|---|
| ADD | primitive secondary/ghost additions | trajectory policy may request additions | plans segments |
| DROP | absent | primitive drop plus trajectory policy | delegates segments |
| DISPLACE | absent | absent in current primitives | absent |
| ACCENT | no mutation in `addVariation` | gate/trajectory policy only where source requests it | delegates segments |
| GHOST | primitive addition | legacy plan mutation available | delegates segments |
| orchestration | none | trajectory selection and per-bar policy | 4+4 segmentation/context |
| Phrase planning | none | none | request validation and segment planning |

## Stack baseline interpretation

Host GCC `.su` output is a comparison baseline. **It is not ESP32-S3 runtime
stack high-water mark.** Nested estimates must follow actual caller chains and
must not sum unrelated translation-unit frames.
