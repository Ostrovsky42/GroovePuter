# 0.9.9-E1b — real live-bridge characterization

## Purpose

Close the E1 characterization gap by executing the shipped
`regeneratePhraseAuditionWithProbe(MiniAcid&)` caller through the real desktop
MiniAcid/SceneManager/generation graph. This checkpoint does not consolidate
owners and does not change production generation or materialization semantics.

The test compares the live caller with an independently derived production
request to `evolveMultiBarPhrase(...)` for 2, 4 and 8 bars. For 8 bars it also
runs both underlying `evolveRhythmPhrase(...)` segments independently and proves
that the second segment uses `phraseOrdinal N + 1` while reusing the first
`PhraseRhythmIdentity`.

## Fixture feasibility audit

The cheapest real fixture is host-compatible MiniAcid itself:

- `platform_sdl/Makefile` already compiles the production
  `src/dsp/miniacid_engine.cpp`, `scenes.cpp`, all generation owners and
  `src/generation/migration/strong_rhythm_live_bridge.cpp`.
- `MiniAcid(float sampleRate, SceneStorage* sceneStorage)` is host-compatible;
  the runtime test uses the real class and calls `MiniAcid::init()`.
- `SceneStorage*` is not part of the audition caller graph, and the production
  engine guards optional storage access. The deterministic test therefore uses
  `nullptr` rather than inventing a fake storage implementation.
- No fake `MiniAcid`, fake `SceneManager`, fake pattern bank or replacement
  caller is used.
- The normal SDL application `sdl_main.cpp` is excluded only because the test
  supplies its own `main()`; all production engine/generation sources remain
  linked.

## Hardware list

Host integration test only:

None.

## Deterministic state

Each success case resets the real SceneManager with `wipeToZero()` and then
uses:

- page: `0`
- audition bank: Bank B (`1`)
- audition Song slot: Song B (`1`)
- genre: `Techno`
- recipe: base (`0`)
- rhythm selection: `Manual`
- rhythm archetype: `404` (`broken_techno`)
- P-level: `P2Variation`
- FEEL: `Straight`, amount `0`
- tonal root: `C`
- scale: `Dorian`
- requested phrase lengths: `2`, `4`, `8`

Archetype 404 is intentionally used because it is a production-compatible
Techno identity and is enabled by `phraseEvolutionCatalog()`.

## Expected behavior

For each 2/4/8-bar case the runtime output includes:

- `DIRECT ...` with bar count, segment count, trajectories, identity and role
  identity
- one `DIRECT-BAR ...` line per semantic `RhythmBarPlan`
- one `LIVE-BAR ...` line per physical Bank B row with drum/SynthA/SynthB
  fingerprints and Song B references
- `LIVE ... status=EVOLVED ... fallback=false`

The 8-bar case additionally prints:

```text
EIGHT-BAR-SEMANTIC firstBars=4 secondBars=4 ... identity_reused=true ...
EIGHT-BAR-PHYSICAL firstRows=0..3 secondRows=4..7 songBRows=8 semantic_to_live=true
```

The test asserts that every live Bank B drum row is exactly the materialization
of the corresponding direct semantic bar. Therefore rows 0..3 are linked to
semantic segment 1 and rows 4..7 to semantic segment 2, rather than merely
checking `segmentCount == 2`.

The live caller must also publish exactly the requested number of Song B rows,
set Song B length, loop bounds, position 0, active/playback Song B slot and Song
mode.

A real early failure case uses an unsupported genre route. It must return
`SelectionFailed` while leaving Bank B, Song B and bounded transport/selection
state unchanged.

There is no existing production fault-injection seam that can force a failure
after successful selection but during per-bar materialization. E1b therefore
does not add one. `MaterializationFailed` restore is not claimed as runtime
characterized by this checkpoint.

## Troubleshooting

If SDL headers or libraries are missing on Ubuntu/Debian:

```sh
sudo apt-get update
sudo apt-get install -y --no-install-recommends build-essential libsdl2-dev libsdl2-gfx-dev
```

If the test reports `E1B ASSERTION FAILED`, treat the first failing assertion as
an observed production mismatch. Do not update expected data or production
semantics in the E1b branch; report the mismatch and stop.

If `LIVE ...` reports a fallback rather than `EVOLVED`, the real caller did not
exercise the intended phrase-evolution path and E1b must not be marked PASS.
