# 0.9.9-E3a — DROP / DISPLACE exact execution contract

## Purpose

Freeze the missing exact one-delta materialization semantics for `DROP` and
`DISPLACE` under the existing `rhythm_realizer` mutation owner.

This checkpoint defines only **how an already-approved delta changes
`RhythmPhrasePlan`**. It does not choose a delta, enable a production operation,
spend canonical budget, schedule evolution, add lifecycle state, or change UI.

## Hardware

No hardware execution required. Acceptance is a host contract plus Cardputer ADV
and SEQTRAK MIDI-only compile gates.

## E3R-A evidence boundary

E3R-A (`0d160b7a3dd354cef615b8e0413888ea747697cf`, PR #370) is evidence only. It
established that E2c grammar, E2a delta shapes, E2b canonical diff and structural
validation existed, but exact authoritative DROP/DISPLACE materialization did
not. E3a fills only that execution gap.

## Owner

`rhythm_realizer` remains the single mutation execution owner.

```text
E2a proposal
    -> rhythm_realizer exact materialization
    -> E2b diff(original canonical C, materialized W)
    -> E2b canonical-relative budget validation
```

`bar_evolution` remains planning/trajectory only. The executor neither reads nor
updates mutation budget and has no lifecycle/history state.

## API

```cpp
RhythmMutationApplyStatus applyRhythmMutationDelta(
    const RhythmArchetype& archetype,
    RhythmPhrasePlan& plan,
    uint8_t bar,
    BarFunction function,
    TransformationIntent intent,
    const RhythmMutationDelta& delta);
```

Only `DROP` and `DISPLACE` are supported in E3a. `KEEP`, `ADD`, `ACCENT`, `GHOST`
and `Count` do not receive new materialization semantics and fail explicitly.

Every call is atomic: validation and mutation happen on a bounded local
`RhythmPhrasePlan trial`. `plan = trial` occurs only after the result passes
`rhythmMutationPlanValid()`.

## DROP semantics

`DROP` uses the caller-selected `sourceStep`. Exactly one of `structural`,
`secondary`, or `ghosts` must contain the source onset.

On success:

1. clear the source bit from exactly that onset-kind mask;
2. clear `accents` at the source;
3. recompute that role's gates using the existing `recomputeRoleGates()` owner;
4. leave unrelated topology/accent material unchanged;
5. validate the trial plan;
6. commit atomically.

It does not call `bestDropCandidate()`, `clearGhosts()`, Reduction, or Break.

## DISPLACE semantics

E3a supports structural and secondary source onsets only. Ghost displacement is
unsupported.

The target must be empty of structural, secondary, and ghost material. The
executor reuses `rhythmMutationDisplacementGrammarLegal()` for same-lane,
bar-local, non-wrapping radius/protected/forbidden/anchor legality.

On success the source bit is removed and the target bit is added to the **same**
onset-kind mask. Accent state travels with the onset: the source accent is
cleared and the target is accented only when the source was accented. Gates are
then recomputed through `recomputeRoleGates()` and the trial is validated before
commit.

## Coupled-field table

| Field | DROP | DISPLACE |
|---|---|---|
| `structural` | clear if source kind | move if source kind |
| `secondary` | clear if source kind | move if source kind |
| `ghosts` | clear if source kind | unsupported as source |
| `shortGate` | recompute | recompute |
| `heldGate` | recompute | recompute |
| `tieGate` | recompute | recompute |
| `accents` | clear source | move source -> target |

No unrelated topology changes are permitted.

## Atomic failure semantics

Any non-`Success` status leaves every `RhythmPhrasePlan` field unchanged.
Focused tests cover invalid bar/role/shape, unsupported operation, empty or
multiple DROP source, ghost/empty DISPLACE source, occupied target, illegal
radius, protected/forbidden/anchor targets, grammar rejection, and a trial that
fails `rhythmMutationPlanValid()`.

## E2a / E2b boundary

E3a does not modify `produceRhythmMutationCandidates()` or any mutation policy.
The frozen production producer remains:

```text
P1: no candidates
P2: GHOST only
P3: ADD + GHOST only
```

Production DROP, DISPLACE and ACCENT proposal counts remain zero. Synthetic E2a
fixtures may continue to represent those delta shapes.

Focused positive tests feed the exact executor output back to
`canonicalRhythmBarDiff(C, W)`. Every DROP case must round-trip as exactly one
`DROP`; every DISPLACE case must round-trip as exactly one `DISPLACE`.
Canonical-relative budget ownership remains E2b.

## Legacy BarFunction non-change

`applyRhythmBarFunctionMutation()` is unchanged. Historical Reduction/Break
behavior may still clear all ghosts and internally choose a drop candidate.
Exact E3a DROP is a separate lower-level delta contract under the same
`rhythm_realizer` owner and does not redefine legacy BarFunctions.

## Troubleshooting

- `InvalidSource`: the selected source is empty or contains multiple onset kinds.
- `UnsupportedSourceKind`: DISPLACE source is a ghost.
- `OccupiedTarget`: DISPLACE target already contains any onset kind.
- `GrammarRejected`: inspect protected/forbidden/anchor spaces and the existing
  `AnchorTransformRule` for the supplied BarFunction/intent.
- `InvalidResult`: the exact local mutation was formed, but the existing
  structural validator rejected the resulting plan; the original plan is still
  unchanged.
- Source-contract failure: compare against exact base `0992f3d8...`; E3a permits
  production changes only in `rhythm_realizer.h` and
  `rhythm_realizer_evolution.cpp` and requires the legacy executor/E2a producer
  slices to remain byte-identical.
