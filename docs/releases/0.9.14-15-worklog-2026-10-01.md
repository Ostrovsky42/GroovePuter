## Task 2: early USB/RAM gates (read-only screen, 2026-10-01)

Only source and documentation were read. **No device measurement was taken in this stretch.**

### Startup facts (core `m5stack:esp32` 3.2.2)

* With `USBMode=default` + `CDCOnBoot=cdc` (`ARDUINO_USB_CDC_ON_BOOT && !ARDUINO_USB_MODE`), `main.cpp` calls `Serial.begin()` (TinyUSB Device) **before** `initArduino()` and `loopTask`. A role chosen in `setup()` is therefore too late: Device is already running in a Host boot.
* `USBMode=hwcdc` uses USB-Serial-JTAG, which shares the internal PHY with the OTG controller; it is not a route to Host + a console.
* ESP-IDF `usb_host` and TinyUSB Device are mutually exclusive on the single OTG controller.
* Installed core must not be edited (plan rule). The only project-level route found: build with CDC-on-boot off (the old `midi-only` profile in `scripts/build_cardputer_memory_baseline.sh` uses `CDCOnBoot=default`), and start Device or Host from project code after reading the saved role. **Unproven:** TinyUSB and IDF `usb_host` linked into one image, and the consequences below.

### Consequences of that route (to verify, not assumed)

* No early CDC log and no CDC-reset upload path in a Host boot; recovery needs a documented path (BOOT button / download mode). Hardware kit, VBUS source and recovery need the owner.
* A Host-role boot becomes a separate memory profile; a Device boot a separate one.
