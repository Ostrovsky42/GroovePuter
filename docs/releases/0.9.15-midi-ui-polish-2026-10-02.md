# MIDI / PERFORM: UI polish, 2026-10-02

## Решение

Внешняя MIDI-клавиатура следует инструменту PERFORM, когда выбран маршрут `PERFORM`.
Один TARGET управляет встроенной и внешней клавиатурами: SYNTH A, SYNTH B, DX, DRUMS.
DX — внешний MIDI-инструмент, собственного аудио-голоса у него нет.
CHORD, ARP, LATCH и остальные исполнительские преобразования принадлежат существующему PerformanceKeyboard.
Прямые маршруты SYN A / SYN B / DRUMS сохранены: внешняя клавиатура может играть независимо от встроенной.
CHANNEL — входной фильтр OMNI / CH1..16, а не номер инструмента и не настройка выходного канала.
Существующие настройки входа не мигрируют автоматически на PERFORM.

## Интерфейс

- PROJECT: видимая строка разделов SCENES / GROOVE / LED / MIDI; название слева, полное значение справа.
- Вместо бокового блока CPU/RAM — подсказка для выбранного параметра. Сохранённая роль USB и реально активная роль различимы; ожидающий перезапуск USB не получает ошибочное Apply:ACTIVE от состояния Device Profile.
- PERFORM: пятая вкладка IN. INPUT, CHANNEL, ROUTE, TARGET, OUT, USB.
- IN и PROJECT редактируют одну сохраняемую MidiInputRoutingConfig. TARGET / OUT используют существующие контроллеры PERFORM, а не отдельные копии настроек.
- При прямом маршруте TARGET / OUT показывают N/A: изменение инструмента PERFORM не должно переназначать независимый вход.
- IN / TARGET освобождает удержанные ноты предыдущего инструмента через существующий cycleTarget. Следующая нота идёт в новый инструмент.
- USB во вкладке IN показывает текущую роль; изменение роли и подтверждение перезапуска остаются в PROJECT / MIDI.
- Tab открывает инструменты PERFORM и переключает вкладки; Backspace идёт назад, поэтому из KEY до IN один Backspace. Стрелки выбирают строку / значение, Escape возвращает к игре. Во время игры также остаётся существующий `\` для TARGET.
- Live PERFORM при отсутствии удержанных нот показывает включённый маршрут входа. Строки статуса ограничены шириной экрана.
- Название темы в PROJECT использует тот же UI::themeName, что общий интерфейс.

## LED

RGB data на ADV восстановлен на GPIO21 по таблице установленной M5Unified (`src/M5Unified.cpp`, board_M5CardputerADV).
Типизированный no-op старого PA enable сохранён: GPIO21 не используется как включение усилителя.
Питание RGB связано с GPIO38 — подсветкой LCD; M5GFX остаётся владельцем этого GPIO, LedManager не переключает его напрямую.
Официальный источник связи питания и подсветки: [M5Stack Cardputer ADV](https://docs.m5stack.com/en/core/Cardputer-Adv).

Добавлена отдельная команда TEST LED: импульс 150 мс с текущим цветом/яркостью, без изменения сцены.
Яркость в сцене остаётся raw 0..255; UI показывает процент от этого диапазона (40 → 16%), сохранённые проекты не переинтерпретируются.
Source / Flash доступны в StepTrig; в остальных режимах видны как неактивные и не редактируются.
RGB-запись остаётся в UI/update, публикация событий — существующий ограниченный атомарный слот. Новый USB или аудио-владелец не добавлен.

## Что требует устройства

- TEST LED и реальные StepTrig / Beat / MuteState, включая взаимодействие RGB-питания с подсветкой.
- Свободная внутренняя память, largest block и минимум стека после инициализации RGB/RMT и USB Host; статическая DRAM не заменяет эти замеры.
- nanoKEY2: удержать ноту/аккорд, сменить TARGET, отпустить клавиши, играть снова; проверить отсутствие зависших нот.
- Входной канал, прямой маршрут и PERFORM, OUT INTERNAL / MIDI / LAYER, настоящий внешний DX-модуль.
- Сохранение настроек и холодный старт, смена USB-роли с перезапуском, реальные клавиши Cardputer и устойчивость звука.

SDL с dummy audio не подтверждает звук, физический RGB, USB Host, DRAM/стек и холодный старт с карты.
