# 0.9.11 C4 MIDI release boundary

Status: canonical scope for the 0.9.11 C4 convergence wave.

## Product boundary

0.9.11 is the **MATERIAL** release. MIDI work in this release is architecture preparation only: transport-neutral parsing/ingress lifecycle, session/liveness state, routing seams, and preservation of the existing MIDI output/transport/persistence stack.

The intended dependency direction is:

```text
UsbDeviceBackend ─┐
FutureUsbHost   ──┤
FutureDin       ──┼→ MIDI ingress/lifecycle → shared MIDI routing/policy
FutureBle       ──┘
```

`MidiIngress`, `MidiSession`, and `MidiRouter` in this release boundary are architectural responsibilities, not a requirement to introduce parallel classes when existing types already own the responsibility. C4 must not create transport-specific musical policy.

## C4 acceptance for 0.9.11

C4 is complete when all of the following are true:

- MIDI bytes/events can be normalized through a backend-neutral ingress primitive.
- Endpoint/session lifecycle has explicit READY/STALLED/disconnect semantics so stale state can be cleared at the transport boundary.
- Existing shared MIDI routing, output, clock/transport, persistence, ownership, and panic semantics remain green.
- Adding a future transport backend does not require a second sequencer, pitch engine, performance-note owner, or transport-specific musical-policy fork.
- Cardputer ADV product build and DRAM budget remain green.

## Explicitly not claimed by 0.9.11

The following are **0.9.12 MIDI / EXTERNAL CONTROL** work, not C4 acceptance criteria:

- external USB Host runtime;
- MAX3421E driver/backend and USB enumeration;
- USB MIDI class host handling;
- real nanoKEY2 hardware acceptance;
- external-controller hotplug/reconnect hardware acceptance;
- external keyboard → PERFORMANCE / ARP integration;
- recording from an external keyboard;
- complete DIN/BLE ingress backends.

The built-in USB MIDI Device and existing MIDI output/transport behavior are preservation subjects in 0.9.11, not evidence that the external Host slice is complete.

## Forward roadmap

```text
0.9.11  MATERIAL
0.9.12  MIDI / EXTERNAL CONTROL
0.9.13  PERFORMANCE / SCENES
0.9.14  COMPOSITION / SONG
```

For 0.9.12, the first external Host implementation should plug into the C4 seam as:

```text
MAX3421E → USB MIDI class → MIDI ingress/lifecycle → shared MIDI routing/policy
```

If that work requires a new transport-specific routing policy or a new live-note owner, treat it as an architecture regression rather than as a normal Host implementation detail.
