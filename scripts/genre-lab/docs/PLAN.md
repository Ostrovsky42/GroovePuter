# План: одно семейство → метод → 16 жанров

Каждый этап заканчивается проверяемым артефактом и решением GO/NO-GO. Без GO следующий этап не начинается.

## Этап 0 — Инструмент (этот архив)
- Готово: ядро, валидатор, кодоген, A/B, тесты, синтетическое демо.
- **GO:** `make test` и `make demo` зелёные у тебя локально.

## Этап 1 — Baseline текущей прошивки
- GroovePuter учится выдавать `takes.jsonl` (PR-1).
- Прогон `gplab validate` на текущих House/Techno/Acid/UKG по **синтетическим** профилям — только проверка, что формат и метрики работают на реальных дублях.
- **GO:** файл детерминирован; diversity на текущих BASE измерен и записан. Ожидаемо низкий — это повторение аудита 2026-11-10 новым инструментом.

## Этап 2 — Корпус пилота (House: base / deep / acid)
- `tags` → поправить `jamendo_tags`; `selfcheck` → поправить `discogs_style`.
- `candidates` → `styles` → `select`.
- **GO:** ≥ 2 варианта набрали ≥ 30 треков. NO-GO-вариант откладывается, а не добирается вручную.

## Этап 3 — Профили
- `analyze` (ADTOF через MIDI, basic-pitch, beat_this, demucs) → `profile` → `codegen`.
- Ревью `profiles.json` глазами: бочка 0/4/8/12 ≈ 1.0, снейр 4/12 высоко, свинг в разумных пределах.
- Калибровка: `gplab holdout --seeds 10` — реальные треки проверяются как дубли. Пороги из `calibration.md` переносятся в конфиг отдельным коммитом.
- **GO:** в `calibration.md` все проверки проходят в ≥ 90% сидов при пороге, который не хуже стартового более чем на 20%. Если для этого порог приходится сильно ослаблять, варианты на этих данных неразличимы: NO-GO по варианту.

## Этап 4 — Генератор (PR-4)
- Клетки и вероятности из заголовка → идиомы новых append-only рецептов House.
- **GO:** `validate` PASS для пилотных вариантов; старые BASE и golden-тесты не изменились; бюджет памяти ADV в норме.

## Этап 5 — Слепой A/B на SEQTRAK
- ABX: варианты различимы на слух (≥ 12/16 на пару).
- Предпочтение: новый генератор против текущего билда (≥ 9/12 на вариант).
- **GO:** ABX значим хотя бы для одной пары соседей, предпочтение не хуже baseline. Иначе — назад к этапу 4, метрики не спорят с ушами.

## Этап 6 — Расширение
Порядок по риску (от простого к сложному):
1. Techno (detroit / dub / industrial) — та же сетка, проверка якорей.
2. UK Garage (2-step / dark skippy) — **сдвиг на 8 неоднозначен**, нужен якорь по бас-линии или 2-тактовый анализ.
3. Acid (уже есть recipe ID) — замер против существующего.
4. Остальные семейства по одному конфигу на PR.

На семейство: новый `config/<family>.yaml`, этапы 2–5, отдельный PR. Не больше одного семейства в работе одновременно.

## Чего не делать
- Не подгонять пороги под желаемый результат после прогона. Порог меняется отдельным коммитом с причиной.
- Не добирать корпус ручным выбором «правильных» треков.
- Не переназначать существующие recipe ID.
